# Bugs / Issues to Fix Later

1. **Judger Node Test Execution (Malware Sandbox)**
   - **Current State**: Judger is running tests via `pytest` locally on the host machine.
   - **Risk**: Extremely high (Zero-Day Vulnerability). Malicious Miners can return malware disguised as output code, which the Judger will automatically execute locally to validate.
   - **Expected Fix**: Update `ai/blockchain/pouw_validator.py` to:
     - Generate `unittest` scripts instead of `pytest`.
     - Execute the tests strictly inside a Docker sandbox (`docker run --rm --network none python:3.10-slim ...`).
     - Alert validators if Docker is not installed or running.

2. **Judger AI Test Generation Timeout & Flakiness**
   - **Current State**: `test_delete_files_in_directory` generated by the AI expects `/app/target_directory` to exist, but it doesn't, causing `FileNotFoundError`.
   - **Risk**: Valid code submitted by honest miners might get rejected (REJECTED: Pytest failed) because the AI-generated test is flawed or makes assumptions about directories.
   - **Secondary Issue**: `AI Judge Exception: HTTPConnectionPool... Read timed out (read timeout=60)` means local Ollama generation took longer than 60 seconds.
   - **Expected Fix**: 
     - Increase the timeout for the local LLM validation logic.
     - Improve the validator's prompt to generate robust testing code that creates any necessary mock files before asserting on them.
